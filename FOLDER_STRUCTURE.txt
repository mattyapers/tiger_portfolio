FOLDER STRUCTURE — What Each File Does & Where It Goes
======================================================

tiger_portfolio/                    ← YOUR PROJECT ROOT (create this folder first)
│
├── config/                         ← SETTINGS & SECRETS (never share this folder)
│   ├── __init__.py                 ← Empty file. Tells Python "this folder is a package"
│   ├── settings.py                 ← Your portfolio rules, Tiger ID, thresholds
│   └── tiger_private_key.pem       ← YOUR RSA PRIVATE KEY (from Tiger developer portal)
│
├── modules/                        ← THE PIPELINE CODE (3 stages)
│   ├── __init__.py                 ← Empty file. Same purpose as above
│   ├── extract.py                  ← Stage 1: Pulls data FROM Tiger Brokers
│   ├── transform.py                ← Stage 2: Calculates metrics, signals, scores
│   └── load.py                     ← Stage 3: Writes results TO Excel
│
├── output/                         ← WHERE RESULTS GO (auto-generated)
│   ├── portfolio_tracker.xlsx      ← The Excel file you open and review
│   └── run_20260306_2000.log       ← Log file for each run (for debugging)
│
├── main.py                         ← THE BUTTON YOU PRESS (orchestrates everything)
└── README.md                       ← Documentation


WHY THIS STRUCTURE?
===================
This is called "modular architecture." Same concept as your Excel tracker
having separate sheets (Holdings, Rebalance, Dashboard) instead of one
giant sheet. Each file has ONE job:

  settings.py   = "What are my rules?"       (CONFIGURATION)
  extract.py    = "What do I own right now?"  (DATA IN)
  transform.py  = "What should I do?"         (LOGIC)
  load.py       = "Write it down for me"      (DATA OUT)
  main.py       = "Run all of the above"      (ORCHESTRATOR)

If you want to change a rebalance threshold → edit settings.py
If Tiger changes their API → edit extract.py
If you want a new metric → edit transform.py
If you want a new Excel sheet → edit load.py

Nothing else breaks. That's the point of modular design.


WHAT ARE __init__.py FILES?
===========================
These empty files look useless, but they're essential. They tell Python:
"Hey, this folder contains importable code."

Without them, `from modules.extract import extract_all` would fail
with "ModuleNotFoundError" because Python wouldn't recognize
the `modules/` folder as a package.

SQL analogy: It's like creating a SCHEMA in a database.
You can't query `schema.table` unless the schema exists first.


WHAT IS A .pem FILE?
====================
PEM = Privacy Enhanced Mail (historical name, don't worry about it).

It's a text file containing your RSA PRIVATE key. It looks like this:

    -----BEGIN RSA PRIVATE KEY-----
    MIIEowIBAAKCAQEA7x2m0... (long string of characters)
    ...many more lines...
    -----END RSA PRIVATE KEY-----

This is NOT your public key. Tiger gives you a KEY PAIR:
  - PUBLIC KEY  → you paste this ON Tiger's website (they keep it)
  - PRIVATE KEY → you download this TO your computer (you keep it)

HOW RSA AUTHENTICATION WORKS (simplified):
  1. Your code signs each API request with your PRIVATE key
  2. Tiger verifies the signature using your PUBLIC key
  3. If the signature matches → request approved
  4. If not → request rejected

It's the same concept as SSH keys for GitHub, or how your bank
app uses a certificate to prove it's really your bank.

SECURITY RULE: Never commit your .pem file to GitHub.
               Never share it with anyone.
               Never paste it in a chat.
